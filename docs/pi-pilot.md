# Pi 工作流原型使用说明

这是供开发者验证方法的 CLI 入口。Mac 桌面预览版的操作与构建见[桌面试用说明](desktop-pilot.md)。

## 首个可试用的 Agent

“项目接手与优化助手”面向已有的 AI 开发项目。直接说“帮我接手并优化这个项目”，它应调查运行方式和主要问题，与你选定本轮范围，确认后实施和检查，最后交付运行说明、遗留事项与项目经验。

新任务默认使用该助手；明确的新功能或修复需求可选择原有“通用开发助手”。可以自然语言说“使用通用开发助手完成这个功能”或“有哪些助手可用”。助手选择保存在任务中，继续任务时恢复原助手；旧任务没有助手字段时保持原通用流程，不被强制迁移。

两个配置本轮共享固定的四个扩展；本次没有增加任意插件组合管理或插件运行隔离。

## 启动

在项目目录执行：

```sh
npm ci --ignore-scripts
npm run check
npm run pi
```

需要 Node.js ≥ 22.19、Python ≥ 3.9、Bash。代码检索还需要 PATH 中可用的 CodeGraph CLI；当前已验证版本为 0.9.4，本项目尚未自动安装该 CLI。当前只在 macOS 验证，Windows 安装和运行尚未验证。

安装完成后，Mac 日常使用可在 Finder 双击本原型目录的 `启动助手.command`，无需输入命令。也可以运行 `npm run pi`，两者都会先显示项目菜单：输入序号后回车，最近打开的项目排在前面；输入 `q` 退出。Mac 选 `0` 打开系统文件夹选择器，其他系统可直接输入项目根目录路径。平台自身明确标为“开发平台本身（不是同事项目）”。

选定后按 Pi 提示信任当前项目，在 Pi 中使用 `/login` 配置获准的模型服务、`/model` 选择模型；不要把密钥写进项目。已有配置会继续使用。扩展和技能都显式加载本原型的固定集合，避免混入其他工具的同名技能。会话下方持续显示项目名称及完整路径。

最近项目记录放在本原型的 `.local/projects.json`，保留十项，不提交 Git；任务与记忆仍在各自项目中。删除该列表仅清空最近入口，不删除项目记忆。记录损坏会提示并保留原文件，仍可使用下方显式路径入口。双击脚本依赖本机已有的 Node、Python 和安装好的原型，不是独立桌面安装包。

首次在无索引项目试用，先由使用者在该项目目录执行 `codegraph init -i`。索引按项目保存在本机，不随代码提交。

## 在同事的项目中试用

在项目菜单选择自己的本地 Git 仓库，或从本平台目录显式指定：

```sh
npm run pi:project -- /path/to/your-project
```

核对会话下方显示的目标项目和完整路径。任务与记忆保存在该项目的 `.trellis`；示例路径需替换为自己的路径。

首次出现 Pi 的 Trust 提示时，核对当前项目后选择当前项目的 Trust，或仅本次会话信任。

进入 Pi 后直接说：

```text
你帮我优化一下当前这个项目，先看看有哪些值得改进的问题。
```

助手应先调查、记录概况和运行说明，提出最多三个有文件依据的问题，再逐题与你确定本轮重点。也可以给出明确的小任务：

```text
先核对 README 的启动说明与实际入口是否一致。
目标是让新同事能够运行和检查项目。
请一次只问一个需要我判断的问题，给出需求、修改范围和实际检查命令。
```

方案准备好后，助手展示需求、改动范围和验收办法，并打开确认界面。你确认后，它继续实现和检查。交付时先看代码差异和检查输出，再在确认界面验收。重新打开同一项目后说“继续上次的优化”，助手恢复尚未验收的任务；有多个候选时让你选择。

若未配置可用模型，先在 Pi 中 `/login`、`/model`。新副本的 CodeGraph 索引尚未建立，可先读文件；需要结构检索时，再由使用者在该副本中执行 `codegraph init -i`。

### 接入入口的范围

`npm run pi:project -- <Git 项目根目录> [--prepare]` 要求指定独立仓库根目录。`--prepare` 只准备并报告路径，不启动 Pi。首次生成最小 Trellis 运行文件和项目规则索引；已有 `.trellis` 时检查必要文件并保留现有配置、规范和任务，不自动升级。初始化不会修改业务源码。

扩展与技能仍从本原型的固定依赖加载，运行时使用目标仓库作为 cwd。启动参数禁用默认扩展、技能、提示模板和上下文发现，避免嵌套副本继承父项目说明；Agent 根据目标项目的规则索引按需读取既有文档。已有模型账号配置继续由 Pi 管理；依赖个人自定义扩展的模型服务尚未适配。

第一轮需要保留本原型目录及其 node_modules；这不是可搬走的独立安装包。Trellis 任务的初始身份为 `pi-pilot`，不是对实际操作者身份的认证。不会自动建索引、推送、部署或运行模型任务。

## 一次任务怎样进行

直接描述目标，例如“给报表增加账号筛选”或“帮我优化当前项目”。普通咨询直接回答；工作请求由助手建立或恢复项目任务。`/storm` 菜单保留为备用入口。

1. 助手先查项目，一次问一个问题。每次回答后把已确认内容写进任务需求，并更新阶段。你可以说“给我看看现在的方案”。
2. 需求收敛后，助手给出做法与检查方式，并打开确认框供你查看和确认。取消不会开始实现；方案在确认期间变化会拒绝旧确认。
3. 助手自动实现、运行检查、修复失败。界面显示当前阶段、正在执行的工具和下一步。检查失败或中断不能进入验收；按 Esc 可中断当前执行。
4. 接手助手用交付报告展示改动、运行方法、实际检查和遗留事项；有可复用经验时附上项目文件来源。验收界面同时展示这些内容。此操作只记录当前任务的验收，不提交 Git、不归档 Trellis 任务、不发布产物。

接手任务没有调查报告不能批准，没有通过的检查和交付报告不能验收。确认后若调查、需求、方案或检查命令改变，需要重新确认。日常执行清单更新不会重复要求确认。业务修改或重新检查会清除旧交付报告，防止用过时内容验收。

调查工具验证引用文件存在且属于本项目，不自动证明诊断正确。助手必须区分“文件写了什么”“源码实际行为”和“运行验证结果”；没有运行过的部分仍标明待验证。

验收前助手还应逐项说明“要求、证据、实际结果和未覆盖范围”。例如配置说明不仅要包含变量名，还要能解释默认值、如何启用、各数据库的用途和依赖。检查仅扫描名称时不能宣称说明完整，静态核对通过也不能称服务运行通过。范围内遗漏先补齐，结论保存在现有交付记录；这项工作法需要实际试用核对，工具本身不会判断文档语义。

## 退出后继续

重新启动，在菜单选择上次的项目（最近打开的排在前面），再说“继续上次的工作”。只有一个未验收任务时直接恢复；有多个时展示选择。它会读取需求文件和阶段继续。原始聊天仍可使用 Pi 自身的 `/resume`。

需要手动排查时，`/storm new`、`/storm resume`、`/storm spec`、`/storm approve`、`/storm accept` 仍可用；这些不是日常使用的必备步骤。

说“查看项目经验”或“之前对清洗规则做过什么决定”，助手会查询本项目已验收的记录。取消验收或尚未完成的交付不会被列为已确认经验；任务归档后仍能读取。最近记录会提供简短上下文，按主题查询可找更早的记录。来源可能随项目变化，使用前核对当前文件。原始聊天的压缩仍由 Pi 负责。

备用入口 `/storm agents` 查看助手，`/storm memory [主题]` 查看经验。`/storm new` 提供助手选择；自然语言新建由模型在任务工具中选择。查看需求与方案也会展示已记录的调查和交付报告。

回顾时可直接问：“上次优化了什么？检查结果怎样？还有哪些遗留问题，哪些是已经决定不做的？”助手应读取完整交付和检查记录，不需要为此建立任务。系统摘要现在附带交付、检查、遗留和原记录位置；内容过长会标注截断，完整内容仍保留。历史检查应注明是上次运行，跳过项说明原因；设计上的“不抽新模块”不能被当作自动待办。

- `.trellis/tasks/<task>/prd.md`：本次需求和验收条件。
- 同目录 `design.md`、`implement.md`：需要时记录方案和执行清单。
- 同目录 `progress.json`：当前助手、阶段、下一步、调查与交付报告、确认指纹、最近一次实际检查结果和验收记录。这是报告与已验收经验的唯一存储来源。
- `.trellis/spec/`：经过整理的项目约定和经验。

交付经验不会自动改写项目规范。成熟约定仍按项目已有方式维护；历史任务记录提供来源和理由。验收后的报告如被手工改变而与验收指纹不符，读取经验会报错，不能把改写内容当作原确认。

不要同时在两个会话修改同一任务；第一轮没有多会话写锁。检查记录只保留最近一次，详细会话另由 Pi 保存。终端外手动修改代码后，应让助手重新检查再验收。

## 已验证和待验证

已通过 `npm run check`：真实 SDK 加载四个扩展、确认/验收门槛、真实命令成功与失败、取消、并行修改与检查互斥、新会话恢复、同名项目隔离。测试替换了模型消息发送，不产生模型调用。

自然语言入口的底层工具回归已通过：未建任务前无法直接改代码、工具建任务与恢复无需命令、同名创建重试不重复建任务、取消方案或验收不推进、确认期间变动方案会拒绝、确认与修改/检查互斥。它验证了模型可调用的工具链，尚未证明真实模型面对宽泛中文请求时的判断质量。

首个 Agent 的离线回归已覆盖：Agent 选择及旧任务指纹兼容、调查和交付门槛、缺失或越界来源、调查变动使方案失效、交付期间变动拒绝验收、修改及重跑检查清除旧交付、取消不形成确认经验、新会话恢复原助手、跨 Agent 的项目经验读取、归档检索、已验收记录变动检测及跨项目归档拒绝。

外部项目接入回归已覆盖：嵌套 Git 仓库禁止误认父项目、重复初始化保留项目记忆、保留原 README、拒绝子目录和不完整配置、拒绝跨项目 Trellis 符号链接，以及检查确实在目标项目执行。

已用隔离的 Pi 配置实际启动外部 Git 项目，在终端确认正确项目目录、四个扩展、`/storm` 中文菜单和 Ponytail FULL。没有发送模型消息或替使用者创建业务任务；隔离配置未配置模型，可选 fd 下载仍受测试环境网络限制。

已在真实 Pi 终端看到 `/storm` 中文菜单与 Ponytail FULL 状态；已通过正式安装的 CodeGraph 扩展执行状态和符号查询。

2026-09-10，内部试用已完成两次小范围改动和历史记忆恢复。试用后补充了项目选择、持续路径展示、完整检查摘要和文档语义验收要求。具体业务仓库、任务记录和私有调查材料不随本仓库公开。

Mac 桌面版的真实登录和界面验证状态见[桌面试用说明](desktop-pilot.md)。其他模型、另一台电脑和更多业务任务的质量仍需分别验证，离线检查不替代业务验收。

确认门槛用于减少 Agent 误操作，不是操作系统沙箱。项目文档、工具和插件必须来自使用者信任的项目。不要手动篡改 progress.json 来伪造检查或批准状态。
