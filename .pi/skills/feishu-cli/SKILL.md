# 飞书 CLI

本产品随包提供官方 lark-cli 1.0.90，不需要安装 npm 全局包。不自建飞书后端、不继承构建者账户、不自动升级 CLI。

## 使用

通过 `storm_lark` 传参数数组（省略可执行文件名），不要用 Bash 绕过确认：

1. `{"args":["skills","list"]}` 找到所需领域。
2. `{"args":["skills","read","lark-shared"]}` 读取身份/安全规则。
3. `{"args":["skills","read","lark-base"]}` 等读取领域技能，按其中引用继续读参考：`{"args":["skills","read","lark-base","references/lark-base-record-query-and-analysis-sop.md"]}`。
4. 用同一工具调用指南里的业务命令，先查 `--help`，显式指定 `--as user` 或用户明确要求的 `--as bot`。联网或业务调用由界面单独确认，不因项目方案已批准而跳过。

上游文档中的 `lark-cli …` 命令在这里转换为args数组；相对Markdown引用通过 `skills read` 读取，不把它当本机文件路径。长文按工具提示offset继续。上游没有内嵌assets/scripts；需要这些资源时说明缺失，不能编造路径或静默下载执行。

代码审查角色只允许离线帮助、技能读取和版本查询，联网/业务调用即使单独确认也不开放；需要业务操作时明确离开审查模式，不绕过限制。其他角色仅离线帮助、技能读取和版本查询免确认。`auth status` 可在确认后检查账户；不能凭工具已加载就说已登录。无UI时业务调用停止。

## 首次配置与登录

第一版不提供专门的飞书登录页面。未配置/未登录时，请用户在原生终端运行CLI并完成浏览器操作：

- 已经用过官方CLI：先检查其已有登录，可能可以直接复用；不要无故重新创建应用、覆盖配置或切换身份。
- 首次使用：原生终端 `lark-cli config init`，再按需要 `lark-cli auth login --domain docs` 等最小业务域授权；具体命令先查该版本帮助。用户完成后再检查状态。
- 若没有全局CLI，使用随包绝对路径。默认Mac安装位置：`"/Applications/MediaStorm Agent.app/Contents/Resources/app/runtime/bin/lark-cli"`；安装位置不同则按实际位置替换。源码版使用平台根目录的 `runtime/bin/lark-cli`，不是业务仓库中的路径。
- 原生终端命令的浏览器链接/二维码由CLI交互提供；不要在对话中索要App Secret、访问令牌或刷新令牌。

配置/登录/升级以及底层`api`不在storm_lark入口开放；不要照搬上游技能在Bash后台登录。需要时说明原生终端操作。内置CLI随产品升级，不在已签名应用目录执行自更新。

## 数据与操作边界

- 默认用户身份；无权限不能自动切成应用身份。最小授权，不为便利申请全部域。
- 发送、写入、删除、发布必须说明目标和影响；上游exit 10不是成功，不自动追加`--yes`重试。
- 非零退出、超时、取消、缺页都不能报告成功；写操作结果不明先查询，不盲重试。
- 大表导出与确定性分析遵循该版本Base SOP：最小字段，数据文件由程序计算，不把整张表或敏感原文自动送给模型。报告写明可见范围、时间和口径。
- 原始业务返回可能进入Pi会话。读取前提醒用户只提供允许进入当前模型/会话的数据；不要把凭据、真实数据或账户文件提交到源码。
- CLI保留上游安全默认值和凭据存储方式。当前集成不是沙箱，也不提供公司级统一审计/权限系统。
